## 2. Входной контракт

В PDF нет полной схемы из упомянутой памятки. Для этого экземпляра принимается следующий рабочий контракт. Поля обязательны; неизвестные поля отклоняются, включая вложенную декларацию. Изменение схемы после получения памятки должно быть отдельным осознанным изменением с тестами.

| Поле | Входной тип | Правило |
|---|---|---|
| submission_id | str | Непустая непробельная строка; новая версия — новый ID |
| student_id | str | Непустая непробельная строка |
| assignment_id | str | Непустая непробельная строка |
| timestamp | str | ISO 8601, с часовым поясом, нормализуется в UTC |
| text | str | Любая строка, включая пустую; сохраняется точно |
| code | str | Любая строка, включая пустую; не исполняется |
| ai_declaration | object | Строго два поля: used (bool), details (str) |

`details` может быть пустой строкой даже при `used=true`. Схема проверяет форму декларации, а полнота пояснения — отдельный будущий анализатор на защите. `used` не является меткой происхождения текста. Строки должны кодироваться в UTF-8. Пробелы в идентификаторах не удаляются; только полностью пустые идентификаторы недопустимы. Даты принимаются в вариантах `datetime.fromisoformat` Python 3.11+ с явным смещением. Не валидируется принадлежность ID студенту или заданию — это вне этапа А.

Пример JSON:

```json
{
  "submission_id": "demo-001",
  "student_id": "student-demo",
  "assignment_id": "lab-1",
  "timestamp": "2026-01-01T09:00:00Z",
  "text": "Учебный пример",
  "code": "print('demo')",
  "ai_declaration": {"used": false, "details": ""}
}
```

## 3. Правила приёма

1. Разбор JSON: синтаксические ошибки, повторяющиеся ключи, NaN/Infinity и некорректный UTF-8 — ошибки формата.
2. Проверка схемы: обязательные поля, типы, непустые ID, часовой пояс, структура декларации. Одна объяснимая ошибка на запись (fail-fast).
3. Создание `Submission`, состоящей из неизменяемых значений и вложенной frozen dataclass; внешняя структура не модифицируется и не хранится по ссылке.
4. Расчёт SHA-256 по JSON всех полей, включая идентификаторы, UTC timestamp, текст, код, декларацию. Канонизация: сортировка ключей, фиксированные разделители, UTF-8, без нормализации текста. Разная запись одного момента времени считается одинаковой; любое изменение содержательных полей — другой хеш.
5. Нет записи по ID — сохранить и вернуть `accepted`. Есть тот же хеш — вернуть `duplicate` и именно ранее принятую модель. Другой хеш — `ConflictError`, исходная запись не меняется.

`SubmissionRepository` — структурный контракт с `get` и `add`; реализация не обязана наследоваться от него. Сервис получает зависимость через композицию. Поиск по словарю в среднем O(1), вычисление хеша и разбор — линейны по размеру сдачи (с учётом фиксированного набора ключей). Хранение — O(суммарного размера принятых сдач). Нет транзакций или гарантий конкурентного доступа.

## 4. Ошибки и ресурс

| Код | Причина |
|---|---|
| format_error | Строка не является корректным однозначным JSON |
| schema_error | JSON разобран, но контракт нарушен |
| conflict | ID закреплён за другим содержимым |

Каждая ошибка содержит `code`, `field`, `message`; отчёт импорта добавляет `line` (с 1). `$` означает строку или объект целиком. Неизвестное поле указывается по имени; содержимое работы и исходный JSON не добавляются в отчёт. Пустые строки JSONL считаются ошибочными. В файловом адаптере `with` закрывает поток при штатном завершении и исключении. Ошибки отдельных сдач не останавливают цикл; ошибки ввода-вывода завершают CLI кодом 2; неожиданные программные ошибки не маскируются.

## 5. Тестирование и измерения

Команды в README. Фактическая исходная проверка: [verification-initial.md](verification-initial.md). Перед публикацией локальный скрипт `scripts/verify.py` записывает результаты в `docs/verification-local.md`. Синтетические данные, нет реальных работ студентов. Набор тестов включает позитивные и негативные сценарии, неизменность, сохранение исходной записи после конфликта, продолжение после повреждённой строки, освобождение ресурса и CLI.

Измерение: `scripts/benchmark.py`, 1000 синтетических записей, 5 прогонов с новым репозиторием; сначала новые, затем повтор тех же записей. Медианы 21.40 мс и 19.04 мс соответственно в Linux/Python 3.13.5. Замер включает валидацию, хеширование и поиск/сохранение, не включает файловый ввод-вывод. Значения зависят от машины; это не сравнительный тест альтернативных реализаций.
